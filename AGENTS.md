## Background: why the Caps Lock mapping exists

The user types with WeChat Input Method (微信输入法) and switches between two layers of input:

- **Chinese / English inside WeChat IME**: WeChat IME only supports toggling this with a lone Shift tap (press and release Shift with no other key in between). The user prefers to toggle with Caps Lock, so a lone Caps Lock press is mapped to `left_shift`. Tapping Caps Lock alone **must** keep producing a clean lone Shift tap so WeChat IME toggles Chinese/English — do not make it `lazy` or otherwise suppress it.
- **WeChat IME ↔ macOS built-in English keyboard (U.S., `com.apple.keylayout.US`)**: macOS switches input sources with the real Caps Lock key ("Use Caps Lock to switch to and from ABC"). Since Caps Lock is now Shift, Shift + Caps Lock is mapped to send the real `caps_lock` so the user can still switch input sources.

Constraint for the Shift + Caps Lock combo: it must switch input sources **without** WeChat IME also seeing a lone Shift tap (which would toggle Chinese/English as a side effect). That is why the combo sends `shift + f20` before `caps_lock` — the F20 key event sits between Shift down and Shift up so the IME does not treat it as a lone Shift tap.

Known issue (accepted by the user): WeChat IME still occasionally toggles Chinese/English together with the input source switch. EventViewer confirmed Karabiner emits the intended `shift↓ f20↓↑ shift↑ caps_lock↓↑` sequence every time, and sending only `shift + f20` (no `caps_lock`) never toggled, so the problem is tied to the Caps Lock input source switch racing the IME. A 100ms gap between Shift up and `caps_lock` did not help. Also, if Caps Lock lands before Shift, the plain `caps_lock → left_shift` manipulator matches instead and the combo becomes a lone Shift tap — press Shift first.

Alternatives tried and rejected by the user:

- Ctrl + Shift with a `lazy` Shift. Rolling the keys quickly (Ctrl down → Shift down → Ctrl up → Shift up) made the physical Ctrl key up flush the lazy Shift to the OS, which WeChat IME saw as a lone Shift tap. Making Ctrl globally `lazy` fixed it, but a lone Ctrl tap then never reached apps, which the user did not accept.
- Ctrl + Option (tap) and Ctrl + Esc toggling via Karabiner's `select_input_source` between U.S. and WeChat IME (`com.tencent.inputmethod.wetype.pinyin`). These avoid Shift entirely, but the user preferred to keep Shift + Caps Lock.
